# 🇬🇧 English

## 1. Project Description

**Sembrando Huellas Perú** is a non-profit web platform dedicated to the protection and conservation of endangered species in the Madre de Dios region of Peru. The project promotes reforestation, environmental education, sustainable tourism, and community engagement through volunteering and donations.

The platform serves as a digital hub for:
- Showcasing conservation programs and projects
- Cataloging local flora and fauna species
- Publishing environmental education content
- Managing volunteer registration
- Processing online donations
- Displaying impact metrics and gallery media

## 3. Architecture Overview

The project follows a **Feature-based Architecture** where each domain concern is encapsulated within its own feature directory. Shared code lives in top-level directories.

```
┌─────────────────────────────────────────────┐
│                  App (Provider Shell)         │
│  ┌─────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ TanStack │ │  React   │ │  React Router│ │
│  │  Query   │ │ Contexts │ │   (Routes)   │ │
│  └─────────┘ └──────────┘ └──────────────┘ │
├─────────────────────────────────────────────┤
│                    Layouts                    │
│  MainLayout · AdminLayout · BlankLayout ·    │
│  ErrorLayout                                 │
├─────────────────────────────────────────────┤
│                    Features                   │
│  ┌─────────────────────────────────────────┐ │
│  │  feature/                               │ │
│  │  ├── pages/     (Route Pages)           │ │
│  │  ├── components/ (UI Components)        │ │
│  │  ├── hooks/     (Logic Hooks)           │ │
│  │  ├── services/  (API Calls)             │ │
│  │  ├── types/     (TypeScript Types)      │ │
│  │  ├── interfaces/ (Public API)           │ │
│  │  ├── data/      (Local Data)            │ │
│  │  ├── constants/ (Feature Constants)     │ │
│  │  ├── styles/    (Styles)                │ │
│  │  └── animations/ (Animations)           │ │
│  └─────────────────────────────────────────┘ │
├─────────────────────────────────────────────┤
│                Shared Layers                  │
│  components/ui · hooks · services ·          │
│  lib · config · contexts · types ·           │
│  locales · data · utils                      │
└─────────────────────────────────────────────┘
```

**Key principles:**
- **Lazy loading** at route level via `React.lazy` + `Suspense`
- **Code splitting** via Vite `rollupOptions.output.manualChunks`
- **Centralized configuration** through `src/config/`
- **Environment-aware** via typed `env.ts`
- **i18n-first** navigation labels referenced by translation keys

## 5. Conventions

### Naming

| Entity | Convention | Example |
|--------|-----------|---------|
| Components | PascalCase | `PrimaryButton`, `GlassCard` |
| Hooks | camelCase, `use` prefix | `useMediaQuery`, `useDebounce` |
| Services | camelCase | `api.ts`, `auth.ts` |
| Files | camelCase (kebab-case allowed) | `AppRoutes.tsx`, `SectionTitle.tsx` |
| Types/Interfaces | PascalCase | `BaseEntity`, `Locale` |
| Constants | camelCase or UPPER_SNAKE | `siteConfig`, `API_TIMEOUT` |
| CSS custom properties | kebab-case | `--color-primary` |
| Feature directories | singular kebab-case | `volunteers/`, `not-found/` |

### Code Style

- **Semicolons**: Required
- **Quotes**: Single quotes (JSX uses double quotes)
- **Trailing commas**: Always
- **Print width**: 100 characters
- **Indentation**: 2 spaces
- **End of line**: LF
- **Arrow parens**: Always
- **CSS**: Tailwind utility classes preferred; custom CSS via `style/index.css`

### Git

- **Hooks**: Husky + lint-staged run `oxlint --fix` and `prettier --write` on staged files
- **Branch naming**: `feature/`, `fix/`, `chore/`, `refactor/` prefix
- **Commit style**: Conventional commits encouraged (`feat:`, `fix:`, `chore:`, `docs:`)

## 6. How to Add

### A New Feature

Each feature follows a consistent internal structure. Create `src/features/<name>/` with these subdirectories:

```
src/features/<name>/
├── pages/       # Route page component (default export)
├── components/  # Feature-specific UI components
├── hooks/       # Feature-specific hooks
├── services/    # Feature-specific API calls
├── types/       # TypeScript interfaces & types
├── interfaces/  # Public API barrel exports
├── data/        # Local data files
├── constants/   # Feature constants
├── styles/      # Feature styles
└── animations/  # Framer Motion variants
```

Each subdirectory exports via `index.ts`.

### A New Page

1. Create the page component in `src/features/<name>/pages/<Name>Page.tsx`
2. Add the route in `src/routes/routes.ts` using `LazyComponent`:

```tsx
{ path: 'mi-ruta', element: LazyComponent(() => import('@/features/<name>/pages/<Name>Page')) }
```

### A New JSON Data File

1. Create the file in `src/data/json/<name>.json`
2. Import and use it within the appropriate feature or service

### A New Route

1. Open `src/routes/routes.ts`
2. Add a new route object inside the appropriate layout's `children` array
3. Use `LazyComponent` for code-splitting or a direct element for small components
4. Optionally add the route label to `src/config/navigation.ts` and the corresponding i18n key

```tsx
{ path: 'mi-ruta', element: LazyComponent(() => import('@/features/example/pages/ExamplePage')) }
```

### A New Component

- **UI primitives** go in `src/components/ui/<Name>.tsx` — these are generic, reusable components (Button, Card, Modal, etc.)
- **Layout components** go in `src/components/layout/<Name>.tsx` — Navbar, Footer, Sidebar
- **SEO components** go in `src/components/seo/<Name>.tsx`
- **Feature-specific** components go in `src/features/<name>/components/<Name>.tsx`

## 9. Internationalization

The app supports **3 languages**: Spanish (es), English (en), Portuguese (pt).

- **Framework**: i18next + react-i18next
- **Integration**: Context-driven via `LanguageContext`
- **Translation files**: `src/locales/{es,en,pt}/translation.json`
- **Usage**: `t('key')` from `useTranslation()` hook
- **Navigation labels**: Referenced by key (e.g., `nav.home`, `nav.about`) in `navigationConfig`

To add a new language:
1. Create `src/locales/<code>/translation.json`
2. Add the locale code to `siteConfig.locales` in `src/config/site.ts`
3. Add the locale to the `Locale` type in `src/types/index.ts`

## 11. Performance

### Lazy Loading

All route pages are lazy-loaded using `React.lazy` + `Suspense`:

```tsx
function LazyComponent(importFn) {
  const Component = lazy(importFn)
  return (
    <Suspense fallback={<Loader />}>
      <Component />
    </Suspense>
  )
}
```

### Code Splitting

Vite's `manualChunks` splits bundles into:

| Chunk | Contents |
|-------|----------|
| `vendor` | React, React DOM, React Router |
| `animations` | Framer Motion |
| `forms` | React Hook Form, Zod, resolvers |
| `i18n` | i18next, react-i18next |
| `query` | TanStack React Query |

### Image Optimization

- The `<Image>` component provides optimized image handling
- SVGs used for icons and logos
- Placeholder/Loader shown during lazy route transitions

## 12. Accessibility

The project aims for **WCAG AA** compliance:

- **Semantic HTML**: Proper heading hierarchy (`h1`-`h6`), landmark elements
- **Keyboard navigation**: All interactive elements are reachable via keyboard
- **Focus management**: Visible focus indicators, logical tab order
- **ARIA attributes**: `aria-label`, `aria-expanded` on interactive controls (e.g., Navbar hamburger)
- **Color contrast**: Token-based color system ensures sufficient contrast ratios
- **Reduced motion**: Framer Motion respects `prefers-reduced-motion` via `useReducedMotion`
- **Screen reader support**: Lucide icons use `aria-hidden`; text labels accompany icon-only buttons
- **Form validation**: Zod schemas provide accessible error messages via React Hook Form

## 13. SEO Setup

- **`react-helmet-async`**: Each page sets dynamic `<title>`, `<meta>`, and Open Graph / Twitter Card tags via the `<SEO>` component
- **Structured data**: Schema.org JSON-LD via `OrganizationSchema`, `ArticleSchema`, `BreadcrumbSchema` components
- **`sitemap.xml`**: Pre-generated in `public/`
- **`robots.txt`**: Allows all crawlers, points to sitemap
- **Canonical URLs**: Set per page via `<link rel="canonical">`
- **Open Graph**: `og:title`, `og:description`, `og:image`, `og:type` on every page
- **Twitter Cards**: `summary_large_image` card type configured
- **Preconnect**: Google Fonts preconnect hints in `index.html`

## 14. PWA Setup

The application is PWA-ready using `vite-plugin-pwa`:

- **Service Worker**: Auto-update strategy (`registerType: 'autoUpdate'`)
- **Web App Manifest**: `public/manifest.json` with:
  - `display: standalone`
  - Theme color: `#2D6A4F`
  - Background color: `#F5F5F0`
  - 192x192 and 512x512 icons
- **Offline support**: Configurable via `VITE_ENABLE_PWA` env var
- **Caching**: Static assets are precached by the service worker

## 1. Descripción del Proyecto

**Sembrando Huellas Perú** es una plataforma web sin fines de lucro dedicada a la protección y conservación de especies en peligro de extinción en la región de Madre de Dios, Perú. El proyecto promueve la reforestación, educación ambiental, turismo sostenible y participación comunitaria a través de voluntariado y donaciones.

La plataforma funciona como un centro digital para:
- Mostrar programas y proyectos de conservación
- Catalogar especies de flora y fauna local
- Publicar contenido de educación ambiental
- Gestionar registro de voluntarios
- Procesar donaciones en línea
- Mostrar métricas de impacto y galería multimedia

## 3. Visión General de Arquitectura

El proyecto sigue una **Arquitectura basada en Features (dominios)** donde cada preocupación de dominio está encapsulada dentro de su propio directorio de feature. El código compartido vive en directorios de nivel superior.

**Principios clave:**
- **Lazy loading** a nivel de ruta via `React.lazy` + `Suspense`
- **Code splitting** via `rollupOptions.output.manualChunks` de Vite
- **Configuración centralizada** a través de `src/config/`
- **Consciente del entorno** via `env.ts` tipado
- **Navegación i18n-first** con etiquetas referenciadas por claves de traducción

## 5. Convenciones

| Entidad | Convención | Ejemplo |
|---------|-----------|---------|
| Componentes | PascalCase | `PrimaryButton` |

| Servicios | camelCase | `api.ts` |

### Estilo de Código

- **Punto y coma**: Requerido
- **Comillas**: Simples (JSX usa dobles)
- **Comas finales**: Siempre
- **Ancho de línea**: 100 caracteres
- **Indentación**: 2 espacios
- **Final de línea**: LF
- **CSS**: Preferir utilitarias Tailwind

### Git

- **Hooks**: Husky + lint-staged ejecutan `oxlint --fix` y `prettier --write`
- **Ramas**: Prefijo `feature/`, `fix/`, `chore/`, `refactor/`
- **Commits**: Convencionales (`feat:`, `fix:`, `chore:`)

## 6. Cómo Agregar

### Una Nueva Feature

Crear `src/features/<nombre>/` con:

```
src/features/<nombre>/
├── pages/       # Componente de página (export default)
├── components/  # Componentes UI específicos
├── hooks/       # Hooks específicos
├── services/    # Llamadas API específicas
├── types/       # Interfaces y tipos
├── interfaces/  # Exportaciones públicas
├── data/        # Datos locales
├── constants/   # Constantes
├── styles/      # Estilos
└── animations/  # Variantes de Framer Motion
```

### Una Nueva Página

1. Crear en `src/features/<nombre>/pages/<Nombre>Page.tsx`
2. Agregar ruta en `src/routes/routes.ts` con `LazyComponent`

### Un Nuevo Archivo JSON

1. Crear en `src/data/json/<nombre>.json`
2. Importar desde el feature o servicio correspondiente

### Una Nueva Ruta

1. Editar `src/routes/routes.ts`
2. Agregar objeto de ruta al `children` del layout correspondiente
3. Usar `LazyComponent` para code-splitting

### Un Nuevo Componente

- **UI primitivo**: `src/components/ui/<Nombre>.tsx`
- **Layout**: `src/components/layout/<Nombre>.tsx`
- **SEO**: `src/components/seo/<Nombre>.tsx`
- **Feature**: `src/features/<nombre>/components/<Nombre>.tsx`

## 9. Internacionalización

La app soporta **3 idiomas**: Español (es), Inglés (en), Portugués (pt).

- **Framework**: i18next + react-i18next
- **Integración**: Context-driven via `LanguageContext`
- **Archivos**: `src/locales/{es,en,pt}/translation.json`
- **Uso**: `t('key')` desde `useTranslation()`
- **Navegación**: Referenciada por clave (ej. `nav.home`)
